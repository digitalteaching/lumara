# Lumara · Fassung 1.3: Aushang und Wünsche – Implementierungsplan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Am Leuchtturm hängt ein Aushang mit drei neuen kleinen Aufgaben pro Kalendertag. Dazu hat in jedem Gebiet ein Bewohner einen Wunsch: einen Schatz, den das Kind gegen eine Belohnung eintauscht.

**Architecture:**
- **Ereignisse statt Querverweise:**
  - Die reinen Module melden nur, was passiert ist, mit `emit(state, type, data)` (`js/world/events.js`): `state.events` bekommt einen Eintrag.
  - Nur der Aushang (`js/world/board.js`) liest diese Liste, zählt Fortschritt und vergibt Belohnungen.
  - So entsteht kein Ringimport, und ein Ereignis im Duell zählt, auch wenn es erst in der Welt angezeigt wird.
- **Reine Logik ohne DOM**, getestet in Node:
  - `js/world/board.js`: Tag, Aufgaben, Fortschritt, Belohnungen
  - `js/world/wishes.js`: Wunsch-Bewohner, Wünsche, Eintauschen
- **Szenen:**
  - `js/scenes/boardEvents.js`: Tafel, Ilvys Hinweis, Meldungen
  - `js/scenes/wishEvents.js`: Sprechblasen, Eintauschen
  - Beide hängen sich an die Welt wie Garten, Verstecke und Aufgaben.
- **Spielstand Format 11:** `board`, `wishes`, `events`

**Tech Stack:** wie bisher: ES-Module ohne Abhängigkeiten, `node --test`, Pixelraster aus `js/gfx/palette.js`.

**Spec:** `docs/superpowers/specs/2026-11-21-lumara-freunde-und-verstecke-design.md`, Abschnitte 3, 7 (Fassung 1.3), 8 (Format 11), 10 (Jingle „Aufgabe am Aushang erledigt“) und 11. Das Grunddesign gilt weiter.

**Arbeitszweig:** `feature/aushang` von `main` (2936906, Fassung 1.2.1). Auf `main` kommt der Zweig erst in Task 6.

## Review Focus

1. **Mitternacht und Datum:**
   - Ein Kind spielt über Mitternacht oder stellt die Uhr zurück.
   - Erwartet: Beim nächsten Kartenwechsel gilt der neue Tag mit drei neuen Aufgaben, ohne Absturz.
   - Ein früheres Datum als `board.day` erzeugt keine neuen Aufgaben. Es gilt weiter der gespeicherte Tag, damit man nicht durch Zurückstellen neue Belohnungen holt.
   - → Task 2, Tests.
2. **Doppelte Belohnung:** Ein Ereignis wird zweimal verarbeitet, das Spiel wird beim Verarbeiten geschlossen, oder alle drei Aufgaben werden im selben Moment fertig.
   - Erwartet: Jede Belohnung gibt es genau einmal, den Tagesbonus auch.
   - → Task 2, Tests.
3. **Nicht machbare Aufgaben:** Nur Gebiet 1 ist offen, kein Begleiter mit öffnender Gabe, alle Arten eines Gebiets schon befreundet, keine offenen Wünsche.
   - Erwartet: Es kommen nur machbare Aufgaben und trotzdem immer drei verschiedene.
   - → Task 2, Test über mehrere Spielstände.
4. **Wunsch ohne Schatz und volle Taschen:** Antworten mit Nein, Sternfrucht bei vollem Futter, mehrfaches Ansprechen.
   - Erwartet: Nichts geht verloren, der Schatz wird nur bei Ja genommen.
   - Die Belohnung „Sternfrucht“ wird bei vollem Futter zu einem Stein.
   - → Task 3, Tests.
5. **Alter Spielstand 1.2.1:**
   - Er lädt mit leerem Aushang und ohne Wünsche.
   - Beim ersten Start entstehen Aufgaben und Wünsche, Ilvy weist einmal auf den Aushang hin.
   - → Task 1 und Task 6 (echter Spielstand im Browser).

### Task 2: Der Aushang (ohne DOM)

**Files:**
- Create: `js/world/board.js`, `tests/board.test.js`
- Modify: i18n de/en/fr/es, `sw.js`

**Interfaces:**
- Consumes:
  - `state.events`, `BOARD_KINDS` (Task 1)
  - `areaOpen(state, pack, area)`, `mapOfArea`, `areaName`
  - `FRIENDABLE`, `giftOf`, `friendList`
  - `HIDEOUTS`
  - `AREA_WILD`
  - `AREA_TREASURES`, `rollTreasure`, `addTreasure`
  - `addItem`
  - `gainXp`
- Produces:
  - `todayKey(date = new Date()) → 'JJJJ-MM-TT'` (Ortszeit)
  - `ensureBoard(state, pack, today, rng) → boolean`
    - Gibt `true` zurück, wenn ein neuer Aushang entstand.
    - Neu nur, wenn `board` fehlt oder `today > board.day` (Zeichenkettenvergleich).
    - Sonst bleibt alles, auch bei einem früheren Datum.
  - `feasibleKinds(state, pack) → string[]`: alle Arten, die das Kind jetzt schaffen kann (Regeln unten)
  - `processEvents(state, rng) → News[]`
    - Leert `state.events` und zählt Fortschritt.
    - Markiert fertige Aufgaben und vergibt je Aufgabe einmal eine Belohnung (`rewarded`).
    - Den Tagesbonus vergibt sie einmal (`bonus`).
    - `News = { kind: 'task', index, reward: { item: 'treat' } | { item: 'treasure', treasure } } | { kind: 'bonus', starfruit: boolean, xp: 30, levelBefore }`
  - `taskText(task) → string`: `t('board.task.<kind>', { n, area: Gebietsname })`, der Fortschritt kommt als `board.progress` („{progress} von {n}“) dazu
  - `boardView(state) → { day, tasks: [{ text, progress, n, done }], allDone }`

Regeln (Spec 7.1):
- **Drei verschiedene Arten je Tag**, gezogen mit `rng` aus `feasibleKinds`. `n` kommt aus `CONFIG.board.counts[kind]` (`[min, max]`), bei `befriend`, `treasure`, `visit` und `wish` ist es 1.
- **Machbar heißt:**
  - `befriend`: ein offenes Gebiet mit mindestens einer noch nicht befreundeten Art aus `AREA_WILD[area]`. Gezogen wird eines davon.
  - `hideouts`: Das Kind hat einen Freund mit einer öffnenden Gabe (nicht `sniff`), und in einem offenen Gebiet gibt es ein Versteck dieser Gabe.
  - `streak`, `wildWins`, `notes`, `treasure`: immer
  - `visit`: ein offenes Gebiet außer Gebiet 1, sonst nicht machbar
  - `wish`: Es gibt einen offenen Wunsch (`state.wishes`, `done: false`).
- **Fortschritt:**
  - `befriend`, `visit`: Ereignis mit passendem `area`
  - `hideouts` ← `hideout`, `wildWins` ← `wildWin`, `notes` ← `note`, `treasure` ← `treasure`, `wish` ← `wish`
  - `streak`: zählt richtige Antworten in Folge, eine falsche setzt auf 0
  - Erledigte Aufgaben zählen nicht weiter.
- **Belohnung je Aufgabe:** gewichtet aus `CONFIG.board.rewards`: ein Leckerli oder ein häufiger Schatz eines offenen Gebiets.
  - Der Schatz wird mit `addTreasure` gegeben und meldet `'treasure'`.
  - Dieses Ereignis darf keine `treasure`-Aufgabe desselben Durchgangs erfüllen: Neue Ereignisse aus Belohnungen kommen erst beim nächsten `processEvents` dran.
- **Tagesbonus:** wenn alle drei erledigt sind: eine Sternfrucht (passt sie nicht, `starfruit: false` und stattdessen ein Weitblickstein) und `bonusXp` XP. `levelBefore` steht in der Meldung, damit die Szene Level-Aufstiege zeigen kann.
- **Texte (Deutsch):**
  - `board.task.befriend` „Befreunde ein Wesen in {area}.“
  - `board.task.hideouts` „Öffne {n} Verstecke.“
  - `board.task.streak` „Beantworte {n} Fragen hintereinander richtig.“
  - `board.task.wildWins` „Gewinne {n} Duelle gegen wilde Wesen.“
  - `board.task.notes` „Löse {n} Zettel.“
  - `board.task.treasure` „Finde einen Schatz.“
  - `board.task.visit` „Besuche {area}.“
  - `board.task.wish` „Erfülle einen Wunsch.“
  - `board.progress` „{progress} von {n}“
  - `board.done` „Erledigt!“
  - Bei `{area}` steht der Name mit Artikel, so wie Nebelschilder ihn bilden (`destinationName`-Muster bzw. `areas.<id>.the` der Sprachen).

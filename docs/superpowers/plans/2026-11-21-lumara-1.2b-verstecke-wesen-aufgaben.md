# Lumara · Fassung 1.2, Teil B: Verstecke, neue Wesen, Spielaufgaben – Implementierungsplan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Mit dem passenden Begleiter öffnen sich Verstecke in allen acht Gebieten: Funde mit einer Frage und Wesen-Verstecke mit acht neuen Wesen. Dazu gibt es je Gebiet eine kleine Spielaufgabe. Am Ende geht Fassung 1.2.0 an die Kinder.

**Architecture:**
- **Die Verstecke sind Daten** in `js/data/hideouts.js`, keine Kartenobjekte. Sie liegen auf Feldern, die heute nicht begehbar sind (Wasser, Baum, Fels, Mauer, Wolken …), und man spricht sie vom Nachbarfeld aus an. So ändert sich an keiner Karte, wo man stehen kann.
- **Reine Logik ohne DOM**, getestet in Node:
  - `js/world/hideouts.js`: bereit, wer öffnet, Belohnung, Nachfüllen
  - `js/world/tasks.js`: die Spielaufgaben, mit den Arten `collect`, `order`, `turn` und `follow`
- **Szenen:**
  - `js/scenes/hideoutEvents.js`: Anzeige, Spürnase, „!“, Szene, Frage oder Duell
  - `js/scenes/taskEvents.js`: Spielaufgaben
  - Beide hängen sich wie Garten und Begleiter an die Welt.
- **Die neuen Wesen** sind Arten mit `kind: 'hidden'`. `FRIENDABLE`, Wesen-Buch und Reparatur nehmen sie über die vorhandenen Listen von selbst auf, ein neues Spielstandformat ist nicht nötig.

**Tech Stack:** wie bisher: ES-Module ohne Abhängigkeiten, `node --test`, Pixelraster aus `js/gfx/palette.js`.

**Spec:** `docs/superpowers/specs/2026-11-21-lumara-freunde-und-verstecke-design.md`, Abschnitte 3, 6.4, 6.5, 6.6, 6.7, 8, 9, 10 und 11. Teil A (`2026-11-21-lumara-1.2a-freunde-begleiter-garten.md`) ist fertig.

**Arbeitszweig:** `feature/freunde`, weiter auf dem Stand nach Teil A. Auf `main` kommt der Zweig erst in Task 7.

## Global Constraints

- Alle Regeln aus „Global Constraints“ von Teil A gelten weiter. Dazu gehören:
  - vier Sprachen
  - keine Marken, Man **befreundet**
  - `sw.js`-Liste im selben Commit
  - Bewegung reduzieren
  - Commit-Autor und die beiden Schlusszeilen
- **Kein Feld, auf dem man in Fassung 1.1 stehen konnte, wird zum Hindernis.**
  - Task 3 legt dazu `tests/fixtures/karten-1.1.js` an: Für die acht Gebietskarten stehen dort die Felder, auf denen man in 1.1 stehen konnte (alle Tore offen), als Liste `"x,y"`.
  - Die Liste wird einmal aus `git show 0d04036:js/world/maps/<karte>.js` erzeugt und danach nie geändert.
  - Ein Test prüft, dass alle diese Felder begehbar bleiben.
- **Neue Namen:**
  - Wesen und Gegenstände bekommen in jeder Sprache eigene, kindgerechte Namen.
  - Französische Namen beginnen nicht mit einem Vokal oder `h` (Test in `sprachen.test.js`).
  - Kein Name gleicht einem Wesen oder Begriff aus einem bestehenden Spiel. Der Controller prüft die englischen Namen vor dem Commit von Task 1 mit einer Websuche.
- **Zahlen in `js/config.js`:** `hideouts: { refillMs: 600000, xp: 15, nearRadius: 3, sniffRadius: 6, sceneMs: 1500, sceneMsReduced: 500, rewards: { treasure: 5, treat: 4, berry: 3, starfruit: 1, farsight: 2, shine: 1, rare: 1 } }`
- **Statistik:** Antworten in Fund-Verstecken zählen wie Zettel, über `recordNoteAnswer`, nie als Sieg.
- **Keine Verstecke** an geheimen Orten, in der Höhle oder im Garten.
- **Keine neuen Wege:** Spec 6.5 erlaubt sie („darf“). Sie entfallen bewusst, weil eine gespeicherte Position auf einem Gabe-Weg beim Laden ohne den Begleiter ungültig wäre. Jedes Versteck erreicht man von einem Feld aus, das es heute schon gibt.

## Review Focus

1. **Begleiter wechseln vor einem Versteck:** Ein Kind steht vor dem Versteck, wechselt im Menü den Begleiter und drückt A.
   - Erwartet: Satz, „!“ und Öffnen richten sich nach dem neuen Begleiter.
   - Ein Doppeltipp auf A startet die Szene nur einmal.
   - → Task 4, Test für `canOpen` mit wechselndem `state.companion`, Prüfung im Browser.
2. **App mitten in der Frage schließen:** Das Versteck bleibt voll. Nachgefüllt wird nur nach einer richtigen Antwort, bei Wesen-Verstecken mit dem Start des Duells. → Task 3, Test.
3. **Spielaufgabe abbrechen:** Wer die Karte verlässt, verliert den Fortschritt (ein Tipp sagt es). Gelöst bleibt gelöst, und eine doppelte Belohnung ist unmöglich. → Task 5, Test `solveTask` zweimal.
4. **Verstecke an falschen Stellen:** Jedes Versteck liegt auf einem nicht begehbaren Feld, das zur Gabe passt. Sein Vorfeld ist vom Startfeld der Karte bei geschlossenen Toren erreichbar, und dort steht kein Objekt. → Task 3, Test über alle 40.
5. **Alter Spielstand und Buch 41:** Ein Stand aus 1.0.4 oder 1.1 zeigt 41 Plätze, die neuen als „?“. Der Garten sagt „von 40“. → Task 1, Test; Task 7 mit einem echten Spielstand.

**Interfaces:**
- Produces:
  - `TASKS: { [area]: Task }` mit `Task = { area, map, type: 'collect' | 'order' | 'turn' | 'follow', … }`
  - Objekte der Aufgaben in den Karten: `{ type: 'task', id, task: area, role, index?, prop, x, y, lines? }`
  - Sie stehen auf Feldern, die heute nicht begehbar sind. Ausnahme: Platten (`role: 'plate'`) sind keine Objekte, sondern Felder in `TASKS[area].plates`, ausgelöst beim Betreten.
  - `createRun(task) → Run` (Fortschritt nur für diesen Besuch der Karte)
  - `act(run, objectOrPlate) → { result: 'progress' | 'wrong' | 'solved' | 'nothing', index? }`
  - `solveTask(state, area, rng) → { treasure, treat: true } | null`:
    - der seltene Schatz des Gebiets und ein Leckerli
    - `state.tasks` bekommt `area`
    - ein zweiter Aufruf liefert `null`

Arten:
- **`collect`:** Alle `role: 'item'` ansprechen, in beliebiger Reihenfolge. Ein schon gefundenes zählt nicht doppelt. Danach `role: 'giver'` ansprechen → gelöst.
- **`order`:** `role: 'switch'` (oder Platten) in der Reihenfolge `task.order` ansprechen. Ein falsches setzt mit `wrong` zurück. `role: 'clue'` zeigt die Reihenfolge als Text.
- **`turn`:** Jedes `role: 'switch'` dreht A eine Stellung weiter (0 bis 3). Stehen alle wie in `task.goal`, ist die Aufgabe gelöst. Anzeige wie das Zahnrad-Rätsel der Sternwarte.
- **`follow`:** Sichtbar ist nur die aktuelle Station (`task.stations[i]`). Kommt die Figur auf höchstens 1 Feld heran, geht sie zur nächsten. Nach der letzten Station → gelöst.

Gebiete 1 bis 4 (Spec 6.6, Ideen des Spec, der Builder darf ersetzen):

| Gebiet | Art | Umsetzung |
|---|---|---|
| 1 Bucht | collect | drei Möwenküken hinter Booten, Kisten und Büschen; die Möwenmutter am Steg belohnt |
| 2 Wald | order | vier Bäume mit eingeritzten Zeichen, ein Zettelstein nennt die Reihenfolge; dann öffnet sich ein Astloch |
| 3 Moor | follow | ein Irrlicht mit fünf Stationen, am Ende liegt der Fund |
| 4 Dünen | turn | drei Glasstatuen drehen, bis alle zum Leuchtstein schauen |

Texte: je Aufgabe eine Einleitung, ein Satz für jedes Teil, ein Tipp nach einem Fehler, ein Satz beim Lösen und ein Satz danach. Alles in vier Sprachen.
